# GitHub Analyzer 1.4.3

This patch release refreshes the main window's icons and makes repository
information easier to inspect.

## Changes

- The upper-right toolbar uses icon controls instead of text buttons, ordered
  as Refresh pending, Refresh all from GitHub, Manage authorship, and
  Configuration. Short tooltips identify each action.
- Toolbar icons and the University of Deusto logo are displayed at 32 by 32
  pixels. Contribution and alert icons use 28 by 28 pixels.
- Updated contribution, repository visibility, GitHub, and AI alert images are
  bundled with the application. Resource names match the lowercase image files
  so badges and alerts load on case-sensitive systems and from the runnable JAR.
- The repository overview shows the number of branches in the saved original
  download. The repository link moves to the right-hand column and displays
  its GitHub owner and repository name as `owner/repository`.
- Repositories awaiting their first download show `Branches: pending` and
  retain their repository link.
- Status text stays vertically centered when the AI/paste-like alert appears.
  The status bar reserves enough height for its icons and padding.
- The README documents the current toolbar, tooltips, icon sizes, and repository
  overview, with image links matching the bundled resources.

## Downloads

- `github-analyzer-1.4.3.jar` is the self-contained desktop application and
  requires Java 17 or newer.
- `github-analyzer-1.4.3.jar.sha256` is the SHA-256 checksum for the JAR.
- `dependencies.lock.json` and `sbom.cdx.json` describe the bundled dependencies
  and the source distribution.

Keep your existing `resources/` directory when upgrading. GitHub credentials,
repository settings, original downloads, and authorship assignments remain
external to the JAR.

## Validation

All 282 Java tests pass. CI runs the test suite and verifies runnable JAR
contents and licenses with Java 17 on Linux, macOS, and Windows. Desktop
regression checks cover the icon controls, toolbar layout, download cancellation,
and application shutdown. The release workflow builds and verifies the JAR and
its SHA-256 checksum before publishing the download assets.
